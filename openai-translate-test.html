OpenAI Realtime Translate test

The OpenAI twin of the Gemini rigs. This page opens translation sessions to wss://api.openai.com/v1/realtime/translations?model=gpt-realtime-translate configured exactly as the Translator app configures them (OpenAIEngine.swift): the server’s session.created is answered with the app’s session.update — target language en or zh in audio.output.language, source transcription by gpt-realtime-whisper — and the same real-speech clips as the Gemini rigs are streamed as session.input_audio_buffer.append messages, upsampled 16 kHz → 24 kHz by the same linear-interpolation upsampler the app uses. Four tests: T1 English speech into the Chinese session, T2 Chinese speech into the English session, T3 a segmentation probe over one flowing mixed stream (does this endpoint emit ANY per-sentence or per-turn boundary? The Gemini endpoint emits none), and T4 per-sentence latency on the same stream. Verdicts are computed only from parsed message content — transcript text and audio byte counts — never from the socket merely staying open.

The key is read only when a test runs. A browser WebSocket cannot set the Authorization: Bearer header the app sends, so the key travels in the documented browser pattern instead: the WebSocket subprotocols ["realtime", "openai-insecure-api-key.<KEY>"] — the only wire difference from the app, and it changes nothing the server does with the session. The key is never logged, never printed, never stored, and never put in this page’s output or address. Use a throwaway key and delete it after the run.

Two honest differences from the app, both forced by the browser: (1) auth rides in the subprotocol instead of the Authorization header (above); (2) browser WebSocket cannot send protocol-level ping frames (the app pings every 20 s). Test windows here run 17–35 s, so a session the browser holds open is comparable to the app’s behaviour. The third subprotocol token sometimes shown in older examples, openai-beta.realtime-v1, is deliberately NOT sent: the app speaks the GA translation interface (its session.update carries no beta fields), and current OpenAI guidance drops the beta token.
Chinese clip says: “你好,这是一个测试。我想问一下,从这里去机场坐出租车大概需要多少钱?”
English clip says: “Hello, this is a test. Can you tell me where the nearest train station is? I need to get to the airport by three o’clock this afternoon.”

Clips are PCM16, 16 kHz, mono (English 7.32 s / 234,240 bytes; Chinese 7.03 s / 225,024 bytes) — byte-identical to the Gemini rigs’ clips. Each 100 ms frame (3,200 bytes) passes through the upsampler and is sent as one session.input_audio_buffer.append, at real-time cadence, exactly as the app sends its 100 ms capture chunks. Silence frames are digital silence through the same upsampler. After the stream, the page sends session.close (as the app does) and drains for up to 5 s waiting for session.closed. A sentence counts as complete under the app’s own cutter rule (SentenceCutter in CloudEngine.swift): a mark from 。！？.!?；; ends a sentence, except a “.” flanked by digits on both sides (a decimal point). Translated-audio duration is bytes/48000 s (24 kHz, 16-bit mono = 48 bytes per ms).

T3 — Segmentation probe: one English session, flowing mixed stream

        
One en-target session receives: Chinese clip, 1.0 s silence,
          English clip, 1.0 s silence, Chinese clip, then silence to 30 s.
          EVERY server event is counted and timestamped by type; the first occurrence of
          each distinct type is logged raw. The verdict lists any event type that could
          serve as a per-sentence or per-turn boundary — on the Gemini endpoint the
          answer was none, which is why the app cuts sentences client-side.

        

          
          
        

        

      


      

        
T4 — Latency: per-sentence timing on the T3 stream

        
Same stream as T3, same en-target session shape. Per clip, relative
          to the clip’s speech end (t0 = clip end; negative = arrived before the
          speech ended): first translated-audio byte, first output-transcript character,
          first COMPLETE output sentence, first complete INPUT sentence. Clips 1 and 3
          (Chinese) are this session’s direction (MATCHING); clip 2 (English) is
          the wrong-direction row (OTHER) — what the app’s playback gate
